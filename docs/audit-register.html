Resolved during this audit

  • C1 — JWT signing key and admin password present in git history. Key rotated to 88 chars and both admin password hashes re-derived in each database, with security stamps rotated to kill live sessions. Verified newPasswordAccepted=True, securityStampRotated=True, integrity_check=ok. The historical values remain readable in history and are treated as burned.
  • C2 — a capital letter in an email address locked the owner out permanently. Lookups lowercased the input while writes preserved case, and SQLite compares TEXT with BINARY collation. Fixed on both sides via User.NormalizeEmail and COLLATE NOCASE; migration verified up and down against a copy of real data with zero rows lost. 26/26 tests pass, and the regression test was confirmed to fail without the fix.

Verified strengths

Established by exhaustive search or direct code reading, not assumed. These should survive any remediation.

  • No injection of any class. Zero FromSqlRaw, Html.Raw, Process.Start, BinaryFormatter, or server-side HttpClient — so no SQL injection, no view XSS, no command injection, no unsafe deserialization, no SSRF surface.
  • CSRF protection on all 18 MVC POST actions, counted individually.
  • Instant session revocation — the security stamp is re-validated on every authenticated request in both apps, and fails closed.
  • Open redirect blocked by Url.IsLocalUrl.
  • Mass assignment closed — no InstructorId or ImageUrl on the course DTO, no Role on register, owner forced from the token.
  • Uploads are sound at the core — server-generated GUID filenames, traversal blocked with a passing test, stored outside the web root, orphan cleanup on metadata failure.
  • IDOR closed on enrollment and user endpoints.
  • CORS fails closed on empty or wildcard origins and is never combined with credentials.
  • Stable pagination — every sort carries an Id tiebreaker, so no row is duplicated or skipped between pages.
  • WAL enabled on both databases; migrations guarded by __EFMigrationsLock; auto-migration off in production by default.
  • Flutter uploads are genuinely local, with extension allowlists mirroring the server exactly.
  • Course preview before saving is real, and authenticated video streaming works via an Authorization header against a range-enabled endpoint.

Open high-severity findings

Fourteen findings. Each carries its evidence path and how it was established.

Error contract

SEC-S8 Upload failures never tell anyone why proved by code read

ExceptionHandlingMiddleware.cs:68-71, both apps. ArgumentException becomes 400 with the real message discarded and replaced by "One or more request values are invalid." Every carefully written validation reason — the 50 MB limit, the rejected extension — is thrown away. Flutter's error extractor reads exactly that detail field.

Fix a ValidationException carrying a safe user-facing message surfaced in detail. Test assert the size and extension reasons reach the client verbatim.

SEC-S1 Internal detail leaked, and accounts enumerable proved by code read

ExceptionHandlingMiddleware.cs:76-79. InvalidOperationException returns 409 with ex.Message verbatim, leaking configuration text such as "JwtSettings:Secret is not configured." to anonymous callers, and enumerating accounts via "User with this email already exists."

Fix map to a generic 409; introduce a conflict type carrying only vetted messages. Test assert configuration text never appears in a response body.

FUNC-F6 Raw exception text rendered into the MVC UI in 11 places proved by code read

Seven in AdminController, two in EnrollmentsController, two in CoursesController. This is a workaround for SEC-S8 swallowing messages, but it surfaces internal text to end users.

File upload

SEC-S13 Content-type validation is fully bypassable, and no signature check exists proved by code read

CourseAssetService.cs:274 and :297 both return true the moment the declared type is application/octet-stream — a value the client controls entirely. The MIME check therefore contributes no security value at all, and there is no magic-byte validation anywhere in the project despite being an explicit requirement. The extension allowlist is the only real gate.

Fix drop the octet-stream bypass, sniff signatures for JPEG/PNG/WebP/MP4/PDF/ZIP, and persist a server-derived content type. Test upload a .png containing HTML and expect 400.

SEC-S14 Cover replacement is not atomic and can break a cover permanently proved by code read

CourseAssetService.cs:127-175 with CourseAssetRepository.cs:28. AddAsync commits immediately, so if the following course update fails, the catch deletes the new file but leaves the committed metadata row — and the old row is already gone. The cover is then permanently unresolvable. No transaction spans the operation anywhere in the codebase.

Fix one transaction around the replacement; delete the old file only after commit. Test fault-inject mid-replacement and assert the cover still resolves.

SEC-S15 512 MB accepted against a 50 MB cap, with no upload rate limiting proved by code read

RequestSizeLimit(512MB) sits on attachment upload in both apps while the service cap is 50 MB, so 512 MB is spooled to disk before rejection. No EnableRateLimiting on any upload endpoint — throttling is applied to authentication only.

Fix per-type size limits, streaming multipart with a hard ceiling, and an upload limiter. Test assert 413 for oversized and 429 on burst.

Data

DATA-D1 UTC is lost end-to-end, and the two clients guess in opposite directions proved by command

SQLite stores timestamps as 2026-08-26 13:50:41.9517705 — no Z, no offset — so DateTimeKind is lost on read and the JSON carries no designator. Flutter then guesses inconsistently: enrolledDate uses .toLocal() while createdAtUtc uses .toUtc(). On a UTC+3 machine both are wrong by three hours, in opposite directions. Only expiresAtUtc is correct, because it is computed in memory and keeps its kind.

Fix persist and serialize with an explicit UTC designator; make the client parse strictly. Test a serialization contract test asserting the Z suffix survives a round trip.

Cross-client consistency

FUNC-H3 Every MVC-uploaded cover renders as a broken image proved by code read

CourseAssetService.cs:152 hardcodes ImageUrl = "/api/course/{id}/cover", but MVC serves covers at /Courses/Details/{id}/Cover. Three views render <img src="@course.ImageUrl"> and all three 404. Flutter is unaffected because it resolves the path against its API base URL.

FUNC-F1 A cover can be replaced but never removed proved by code read

The asset listing filters out cover images, so no client can ever learn a cover's asset id — and the delete endpoint requires one. Nothing clears Course.ImageUrl either. The Flutter UI states the limitation outright: "leave empty to keep the current cover".

FUNC-F2 Admin tables are configured for a different library than the one loaded proved by code read

site.js:13-25 passes searchable, sortable, perPage, perPageSelect and labels — simple-datatables options — while the layout loads DataTables.net 2.1.8, which expects searching, ordering, pageLength and language. The configuration is ignored and the tables render with English defaults, contradicting the Arabic requirement.

Flutter client

FLU-FL1 Android Emulator has no working configuration at all proved by code read needs runtime check

Three issues compound. API_BASE_URL is a compile-time constant defaulting to https://localhost:7026, with no runtime platform switch and no 10.0.2.2. The manifest declares neither usesCleartextTraffic nor a network security config, so Android 9+ blocks http://10.0.2.2:5205. And https://10.0.2.2:7026 fails TLS because the ASP.NET development certificate is self-signed and untrusted on the emulator.

Fix resolve the base URL at runtime per platform, and add a debug-only network security config trusting cleartext to 10.0.2.2.

FLU-FL2 Large video uploads crash the app before any request is sent proved by code read

admin_courses_page.dart:527 picks with withData: true then wraps the bytes in MultipartFile.fromBytes, with no size validation whatsoever. A 2 GB file is materialised whole and then duplicated, so the app runs out of memory before the network call. The cover path, by contrast, does check 5 MB.

Fix validate against the server caps before reading, and stream from a path rather than buffering bytes.

FLU-FL3 No 401 handling anywhere, so revocation strands the user proved by command

The entire client contains exactly one status-code check — a 403 in the course details page — and logout() is only reached from two explicit taps. Any server-side revocation (password change, role change, deactivation, or the JWT secret rotated during this audit) leaves the app apparently authenticated with every screen erroring and no route back to login.

Fix intercept 401 centrally, clear the session and let the router redirect. Test a widget test asserting a 401 response drives navigation to login.

FLU-FL4 The declared typeface is not bundled, so all typography is inert proved by command

app_theme.dart:27 declares fontFamily: 'Cairo', but the project contains zero font files, pubspec.yaml declares no fonts: section, and web/index.html has no font link. The app silently falls back to platform defaults everywhere — including Web, where Arabic gets whatever the browser chooses.

Infrastructure

OPS-H9 Continuous integration gates nothing proved by code read

The workflow pins Flutter 3.47.1 while the environment runs 3.35.7 with dependencies deliberately pinned for 3.35, and pull_request.branches is set to main while the default branch is master. No pull request into the main line is ever checked, and CI results do not represent the local toolchain.

TEST-M1 There are no HTTP-level tests, and the API project has none at all proved by code read

Microsoft.AspNetCore.Mvc.Testing is referenced and public partial class Program; exists in both hosts — both unused. The test project references only the web app, so JWT authentication, rate limiting, CORS and the exception middleware are entirely untested.

Why remediation starts with the error contract

One chain, three layers

The Flutter file picker offers video and attachment extensions in a single dialog while the type comes from a separate dropdown. Choose video with a .pdf and the server rejects it correctly — but SEC-S8 discards the reason, so the client reads detail and displays "One or more request values are invalid." A user hits this on a very common mistake and learns nothing. The same blindness applies to the test suite, which is why the error contract is fixed before anything that depends on observing failures.

Remediation order

A real sequence: each step makes the next one verifiable.

  1. CI trust and a test harnessOPS-H9 and TEST-M1. Until CI runs on master with the correct SDK and HTTP-level tests exist, no fix can be shown to be safe.
  2. The error contractSEC-S1, SEC-S8, FUNC-F6. Currently masks every other failure from both users and tests.
  3. The upload gateSEC-S13, S14, S15, S17, plus the client-side guard in FLU-FL2.
  4. Timestamps and the cover lifecycleDATA-D1, FUNC-H3, FUNC-F1. Cheap, user-visible today, and each needs a contract test.
  5. The three Flutter blockersFLU-FL1, FL3, FL4 — emulator connectivity, session revocation, and typography.
  6. HardeningAuthentication (SEC-S2–S5), data integrity (DATA-D2, D6), then accessibility and UI (FLU-FL7, FL8) and the remaining medium findings.
